[R7] GRADIENT_OPTIMIZER: lbfgs -> adam, with NUM_ITERS 20 -> 300 and an LR schedule
     Evidence: the RHS is non-smooth in three separate places —
          np.sign(v1) in dv1dt, np.sign(v2) in the slip branch, and
          np.where(|F| < c2 and |v2| < vf, ...) switching the base between stuck
          and slipping. The loss compounds it: it is a mean ABSOLUTE error,
          |F_exp - F_sim| and |s_exp - s_sim|, whose derivative flips sign at
          every point where a residual crosses zero.
     Why: R7 calls for adam whenever gradients are expected to be noisy, and a
          discontinuous RHS under an L1 loss is that case. L-BFGS builds a
          curvature model and runs a line search, both of which assume a locally
          smooth objective; where the stick-slip switch moves under the
          parameters, that model is wrong and the line search wastes solves.
          adam takes small fixed steps and tolerates the kinks — but only with a
          first-order iteration count, so the three edits go together.
     Edit: <P> GRADIENT_OPTIMIZER = adam </P>   (GRADIENT_OPT/SETTINGS)
           <P> NUM_ITERS = 300 </P>             (GRADIENT_OPT/SETTINGS)
           <P> INIT_VALUE_LR = 1e-3 </P>
           <P> END_VALUE_LR = 1e-5 </P>
           <P> TRANSITION_STEPS_LR = 100 </P>
           <P> DECAY_RATE_LR = 0.9 </P>

[R1] Integrator family: explicit — the current INTEGRATOR = Dopri8 is correct
     Evidence: the same three discontinuities listed above. Dopri8 appears in
          the solver table of lib/LLM/api/diffrax.md as explicit RK (non-stiff)
          and is marked validated.
     Why: an implicit method solves a nonlinear system at every step, and across
          the stick-slip switch that solve cannot converge — the step size
          collapses and the integration fails for ANY MAX_STEPS. Note this
          contradicts the source document, which specifies Kvaerno5; the
          smoothness evidence in its own equations overrides its solver choice.
     Edit: none — no change needed.
     Related: dk/dt = Dk*P with P = |m1*v1*dv1dt| >= 0 and Dk > 0, so k is
          monotonically non-decreasing over the solve — the system stiffens as
          it integrates, and an explicit method's stable step shrinks roughly as
          1/sqrt(k/m1). MAX_STEPS = 10000 may prove tight for the upper end of
          the Dk box; if the fit shows solves failing, raise it before
          questioning the solver family.
